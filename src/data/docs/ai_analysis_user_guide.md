# AI決算分析 (RAG) ユーザーガイド

本ドキュメントは、kabu3.0における「AI決算分析機能（RAGパイプライン）」の仕様と動作原理をユーザー（開発者・アナリスト）向けに解説するナレッジベース（KB）です。

## 1. 概要
kabu3.0のAI決算分析は、単なるLLM（大規模言語モデル）へのテキスト丸投げではありません。決算資料特有の「巨大な表データ」や「複雑な文脈」によるハルシネーション（AIの嘘）を物理的に防ぐため、**Docling + 見出しベースチャンキング + Qdrantハイブリッド検索 (RRF) + Gemma3:12B** を組み合わせた堅牢なRAG（Retrieval-Augmented Generation）アーキテクチャを採用しています。

## 2. アーキテクチャの解説

### 2.1 高精度マークダウン変換 (Docling)
決算PDF（短信・説明資料など）は、まず Python (CUDA対応) 上の `Docling` によって高精度なMarkdownに変換されます。これにより、段落構造や複雑な財務表が崩れることなくテキスト化されます。

### 2.2 見出しベースチャンキング (Header-Aware Chunking)
Markdownを単純な文字数で分割すると、表の列と行が分断されてLLMが数値を誤認します。これを防ぐため、本システムでは `src/scripts/rag/chunker.ts` にて**見出し（`#`, `##`等）単位でセクションを切り出す**ロジックを採用しています。
各チャンクには `[決算短信 > 経営成績等の概況 > 次期の見通し]` といったパンくずリスト（階層メタデータ）が付与されるため、切り出された後でも文脈を見失いません。

### 2.3 真のハイブリッド検索 (Reciprocal Rank Fusion; RRF)
Qdrant（ベクトルDB）を用いた検索において、以下の2つの手法を融合（RRF）しています（`src/scripts/rag/qdrant.ts`）。
1. **密ベクトル (Dense Search)**: `bge-m3:latest` (Ollama) が生成する1024次元ベクトルによる「意味的類似度」検索。多少の表記揺れや異なる言い回しでも関連箇所を拾い上げます。
2. **疎ベクトル (Sparse / BM25 Search)**: QdrantのFull-textペイロードインデックスを用いた「キーワード完全一致」検索。「業績見通し」などの決算特有の定型ワードをピンポイントで打ち抜きます。

これらを組み合わせることで、「キーワードが一致すればスコアが跳ね上がり、表記揺れはベクトルでカバーする」という両方の良いとこ取り（真のハイブリッド検索）を実現しています。

### 2.4 2段階パイプライン（抽出と清書の分離）
LLMの計算ミス（ハルシネーション）を極小化するため、以下の2段階プロセス（Two-Step Pipeline）を採用しています：
1. **Step 1 (ファクト抽出)**: `Gemma3:12B` に「無機質なデータ転記ボット」としての役割を与え、単位変換や計算を一切禁止した状態で、純粋に事実のみをJSON配列として抽出させます。
2. **TS側での単位パース**: 抽出された「50,684,952百万円」などの文字列を、TypeScriptの正規表現を用いて「50兆6849億5200万円」といった正確な日本語通貨単位に変換し、テキスト形式に落とし込みます。
3. **Step 2 (アナリスト清書)**: パース済みの正確なデータを再び `Gemma3:12B` に渡し、「プロの証券アナリスト」として専門用語を用いた高度な文章に清書させます。これにより、計算ミスをゼロに抑えつつ、最高品質のレポート出力（JSONの文字列型）を実現しています。

## 3. 分析結果の読み方 (ダッシュボード)
抽出結果は `toyota_ai_report.json` 等に保存され、フロントエンド（Next.js）の個別銘柄ページにてレンダリングされます。
- **当期実績 (Current Performance)**: AIが読み取った今期の強み・懸念点。
- **次期見通し (Future Guidance)**: ガイダンス数値とリスク要因。
- **前回比較 (Report Comparison)**: トーンの変化（経営陣の自信の度合いや、リスク認識の変化）。
- **AI 総括 (AI Comment)**: 上記を踏まえた証券アナリストとしての総合評価。

## 4. トラブルシューティング
- **エラー: `Embedding API Error: {"error":"the input length exceeds the context length"}`**
  - 原因: 表などの単一段落が長すぎた場合。
  - 対策: `chunker.ts` にて、最大文字数を超えたセクションに対するサブチャンキング（ハードカット分割）が適切に動作しているか確認してください。
- **UIに分析結果が表示されない**
  - 原因: LLMがJSONフォーマットを崩した、またはJSON内に改行が含まれてパースエラーになった。
  - 対策: プロンプト（`analyze_stock_rag.ts`）の「① 改行の絶対禁止」が適切に効いているかログを確認してください。
